Security policyReporting vulnerabilities

How to report a security vulnerability in a Supprocom project, and what happens after you do.

Report a vulnerability →

01 / report

Report privately by email:Emailvulnerabilities@mkn8rn.com→

Please don't open a public issue, discussion or pull request for a vulnerability. Public reports put users at risk before a fix exists.

Send what you know, even if it is incomplete.

A useful report includes:
The project and versionWhat the vulnerability allowsSteps or code to reproduce itWhether you want credit

02 / what happens next

01AcknowledgementYou get a reply confirming receipt within 5 working days.
02AssessmentThe report is reproduced, its severity assessed and the affected versions identified. You are told the outcome.
03FixA security update is released free of charge for every affected version within its support period, as a new package on nuget.org and GitHub Packages.
04DisclosureA security advisory is published on GitHub when the update is available, with a CVE identifier where one applies. You are credited if you wish.
05AuthoritiesActively exploited vulnerabilities and severe incidents are reported to CSIRT Croatia and ENISA, as the EU Cyber Resilience Act requires.

Please give a reasonable time to release a fix before you disclose a vulnerability yourself. If no fix is published within 90 days of your report, you may disclose it.

03 / scope

github.com/Supprocom →

Covered projects

  • Every public Supprocom projectAll active repositories in the Supprocom GitHub organisation, and the packages published from them.
  • See the repositories →github.com/orgs/Supprocom/repositories

Supported versions

  • Five years from releaseEach released version receives security updates for five years from its release date, while the publisher's business is active. The end date is stated with each release.
  • Not coveredArchived or retired projects, and vulnerabilities in third-party dependencies, which belong with their own maintainers. Tell us if a dependency's vulnerability affects a Supprocom project.

04 / quick answers

Is there a bug bounty?

No paid bounty. Every valid report is welcome, and you're credited in the advisory if you wish.

Where do ordinary bugs go?

To the project's GitHub issues. The address above is for security vulnerabilities only.

Will I get into trouble for testing?

Not if you act in good faith: test only your own installations, touch no one else's data, and report privately.

Who handles reports?

The publisher, Obrt mkn8rn, vl. Marko Kopričanec, in Križevci, Croatia, who also writes the fixes.
